# 구매에서 지급까지, 어디서 시간이 걸리나: P2P 프로세스 병목 분석

도료 제조사의 실제 구매 품목 21.7만 건으로, 회사가 물건을 사고 대금을 지급하기까지 어느 단계에서 지연이 생기는지 찾고 점검 우선순위를 제안했습니다.

| | 내용 |
|---|---|
| 문제 | 발주부터 지급까지 어느 단계에서 지연이 생기고, 그 지연은 어떤 공급사에 몰려 있는가 |
| 확인한 것 | 송장 접수 → 대금 지급 단계가 중앙값 43일로 가장 길고, 늦게 지급된 17,165건 중 89.7%가 포장재 공급사 5곳에 몰려 있음 |
| 제안 | 공급사 전체보다 이 5곳의 결제 조건과 지급 일정을 먼저 점검하고, 같은 지연 기준으로 공급사별 지연 비율을 매달 확인 |

| 단계 | 발주 → 입고 | 입고 → 송장 접수 | 송장 접수 → 대금 지급 |
|---|---|---|---|
| 소요일 (중앙값) | 9일 | 8일 | 43일 |

보고서: [요약 6장](reports/P2P_분석보고서_v0.1_요약.pdf) · [전체 16장](reports/P2P_분석보고서_v0.1.pdf)

## 내가 한 일

- 문제 정의: 지연을 단계별 소요일과 공급사별 지연 비율로 잴 수 있게 정의하고, 질문을 가설 5개로 나눔
- 검증: 불가능한 날짜·중복·순서가 뒤집힌 기록의 처리 규칙을 먼저 정하고, 가설마다 기준을 세워 확인. 핵심 수치는 다른 방법과 원본 기록으로 다시 확인
- 제안: 지연이 몰린 공급사 5곳을 점검 우선순위로 좁히고, 매달 같은 방식으로 볼 지연 기준을 제시

---

## 1. 문제 정의

구매에서 지급까지는 발주 → 입고 → 송장 접수 → 대금 지급 순서로 진행됩니다. 지급이 늦어지면 공급사 관계와 자금 계획에 영향을 줄 수 있습니다. 하지만 건별 처리 기록만 봐서는 전체 흐름에서 어느 단계가 막히는지 알기 어렵습니다.

> 발주부터 지급까지 어느 단계에서 지연이 생기고, 그 지연은 어떤 공급사에 몰려 있는가?

이 질문을 데이터로 잴 수 있게 두 가지를 정했습니다.

- 단계별 소요일: 품목마다 발주·입고·송장 접수·지급의 첫 시각을 잡아 단계 사이의 일수를 계산
- 늦은 지급: 송장 접수 후 지급까지 약 98일(97.9일)을 넘긴 품목. 이 데이터에서 가장 오래 걸린 10%의 경계(P90)

그리고 질문을 다섯 가지 가설로 나눠 하나씩 확인했습니다.

| | 가설 | 결과 |
|---|---|---|
| H1 | 지연은 특정 단계에 몰려 있다 | 맞음. 송장 접수 → 지급 단계 |
| H2 | 지연은 소수 공급사에 몰려 있다 | 맞음. 포장재 공급사 5곳이 89.7% |
| H3 | 거래가 많은 공급사라서 지연도 많다 | 아님. 거래량이 비슷해도 지연 비율이 2배 이상 차이 |
| H4 | 지급 보류가 지연의 원인이다 | 일부만 맞음. 보류만으로는 설명 부족 (1위 공급사 0136 기준) |
| H5 | 아직 지급되지 않은 건은 취소·변경·누락·진행 중으로 나뉜다 | 대부분 진행 중(75.5%), 삭제·취소 17.4% |

## 2. 데이터

- 네덜란드 도료·코팅 제조사의 2018년 구매 기록을 익명화한 공개 데이터 (BPI Challenge 2019)
- 이 중 송장이 입고보다 먼저 와도 되는 거래 방식의 품목만 담긴 부분집합 사용 (Zenodo record 17295283, 원본의 86%)
- 품목 표(217,406행)와 활동 기록 표(1,214,244행). 품목 하나에 활동이 평균 5.6건 기록됨
- 기간: 2018년 1월 ~ 2019년 1월
- 공급사 번호(0136 등)는 원본 데이터에서 익명화된 번호

| 표 | 한 줄의 의미 | 분석에 쓴 칸 |
|---|---|---|
| cases | 발주서의 품목 한 줄 | case_id(품목 번호), vendor(공급사), spend_area_text(지출 영역) |
| events | 활동 한 번 | case_id, activity(무슨 일), ts(언제) |

## 3. 가설 검증

### 분석 전: 데이터를 믿을 수 있나

- 확인한 것: 1948년 같은 불가능한 날짜, 같은 시각에 중복된 기록 1,384묶음, 순서가 뒤집힌 기록
- 기준: 이상한 날짜가 있는 품목은 통째로 빼지 않고 그 날짜만 계산에서 제외. 처음에는 품목 193개를 통째로 빼는 규칙을 검토했지만, 해당 품목을 열어 보니 송장 날짜만 이상하고 발주부터 지급까지는 정상이었음
- 결과: 발주·입고·송장 접수·지급이 모두 기록된 172,241품목을 분석 대상으로 확정. 지급 기록이 없는 44,594품목은 H5에서 따로 분류

### H1. 어느 단계가 오래 걸리나 → 송장 접수 → 지급

| | 발주 → 입고 | 입고 → 송장 접수 | 송장 접수 → 지급 | 전체 |
|---|---|---|---|---|
| 중앙값 | 8.9일 | 8.2일 | 43.0일 | 77.1일 |
| P90 (가장 오래 걸린 10%의 경계) | 30.1일 | 42.9일 | 97.9일 | 126.9일 |

- 기준: 같은 활동이 여러 번이면 첫 시각을 사용. 대표값은 평균 대신 중앙값과 P90. 아주 긴 몇 건이 평균을 끌어올리기 때문
- 확인: 지급이 송장 접수보다 먼저 기록된 9건을 빼고 다시 계산해도 중앙값은 42.99일로 같음
- 입고 → 송장 접수가 음수인 품목(8.7%)은 송장이 먼저 와도 되는 거래 방식이라 정상 흐름으로 봄

### H2·H3. 지연은 누구에게 몰렸나 → 포장재 공급사 5곳, 거래량 때문은 아님

- 늦게 지급된 품목: 17,165건 (분석 대상의 10.0%)
- 점검 우선순위 기준: 늦은 지급의 누적 90%를 차지하는 상위 10곳 중, 지연 비율(그 공급사 품목 중 늦게 지급된 비율)이 평균의 3배인 30% 이상
- 결과: 0136(73.2%), 0103(58.5%), 0278(55.4%), 0120(33.6%), 0182(30.0%). 다섯 곳 모두 포장재 공급사이고, 늦은 지급의 89.7%(15,400건)를 차지
- 거래량 때문인지 확인: 0136과 0120은 거래 품목 수가 거의 같은데(10,518 vs 10,411) 지연 비율은 73.2%와 33.6%로 2배 이상 차이. 건수가 아니라 비율로 봐야 하는 이유
- 원본 대조: 0136의 품목 하나(4508044951_00020)를 열어 보니 송장 접수 8/9, 지급 12/7로 계산값 119.9일과 일치

### H4. 지급 보류 때문인가 → 일부만

- 비교: 0136에서 보류 해제 기록이 있는 비율은 늦은 품목 57.9%, 늦지 않은 품목 42.5%. 차이가 작아 보류가 주원인이라고 보기 어려움
- 사례: 위 품목은 송장 접수 다음 날 보류가 풀렸는데, 그 뒤 지급까지 약 4개월이 더 걸림. 지연은 보류 때문이 아니라 보류가 풀린 이후에 생김
- 한계: 보류를 건 기록은 52건뿐이라(해제 기록은 54,458건) 해제 기록으로 간접 판단. 다른 공급사는 아직 비교하지 않음

### H5. 아직 지급 안 된 44,594품목은 어떤 상태인가 → 대부분 진행 중

| 상태 (마지막 활동과 시각 기준) | 품목 수 | 비중 |
|---|---|---|
| 진행 중 (2018년 10월 이후에 마지막 활동) | 33,673 | 75.5% |
| 삭제·취소로 이탈 | 7,774 | 17.4% |
| 기록 끊김 후보 (2018년 9월 이전에 멈춤) | 3,089 | 6.9% |
| 변경으로 멈춤 | 58 | 0.1% |

- 기준: 데이터 마지막 달(2019년 1월)에서 약 98일 안에 마지막 활동이 있으면 진행 중. 늦은 지급 기준과 같은 숫자로 맞춤
- 확인: 경계를 한 달 늦춰(2018년 11월 이후) 다시 계산하면 진행 중은 30,500품목, 미지급의 68.4%로 줄지만 여전히 가장 큰 비중이라 결론은 같음
- 미지급의 57.8%(25,778품목)는 송장까지 받고 지급만 없는 상태. H1의 송장 접수 → 지급 병목과 같은 방향이고, 우선 점검 5곳 중 4곳이 미지급 상위에도 있음

## 4. 결론과 제안

결론
- 물건과 송장은 각각 9일, 8일 안팎에 처리되지만, 송장 접수 후 대금 지급까지는 보통 43일이 걸림
- 늦은 지급은 포장재 공급사 5곳에 몰려 있고, 거래량보다는 공급사별 조건이나 절차의 차이일 수 있음
- 지급 보류는 지연을 설명하지 못함. 보류가 풀린 뒤에도 오래 기다린 품목이 있음

제안
- 지급 담당 부서가 이 5곳의 결제 조건과 지급 일정을 먼저 확인
- 송장 접수 후 98일 초과를 지연 기준으로 고정하고, 공급사별 지연 비율을 매달 같은 방식으로 확인. 이번 분석과 같은 쿼리 구조로 월별 점검 가능

## 5. 결과를 어떻게 확인했나

| 확인 방법 | 사례 | 결과 |
|---|---|---|
| 같은 숫자를 다른 방법으로 다시 계산 | 아직 지급 안 된 품목 수를 두 가지 쿼리로 계산 | 둘 다 44,594건 |
| 실제 기록을 열어 대조 | 1위 공급사의 품목 하나(4508044951_00020) | 송장 접수 8/9, 지급 12/7. 계산값 119.9일과 일치 |
| 처리 규칙을 데이터로 재검토 | 이상 날짜가 있는 품목 193개를 통째로 제외하는 초기 규칙(AI 도구 제안)을 검토했더니, 예시 품목은 발주부터 지급까지 정상 | 날짜만 제외하는 규칙으로 변경 |
| 예외 기록이 결론을 바꾸는지 | 지급이 송장보다 먼저 기록된 9건을 빼고 다시 계산 | 중앙값 42.99일로 동일 |
| 기준을 바꿔도 결론이 같은지 | 진행 중 기준을 한 달 늦춰 다시 계산 | 75.5% → 68.4%, 여전히 가장 큰 비중이라 결론 동일 |
| 처음부터 다시 실행 | 명령 한 줄로 모든 쿼리 재실행 | 기록해 둔 수치와 모두 일치 |

AI 도구는 쿼리 초안 작성과 문서 정리에 활용했습니다. 초안으로 나온 숫자는 위 방법으로 직접 확인한 뒤 채택했고, AI 도구가 제안한 처리 규칙 하나는 데이터로 확인해 바꿨습니다(위 표 3행). 질문, 측정 기준, 판단 기준, 결론은 직접 정했습니다.

## 6. 한계와 다음에 볼 것

한계
- 지연 기준(약 98일)은 이 데이터 안에서 가장 오래 걸린 10%의 경계라는 상대 기준. 실제 결제 조건 대비 늦었는지는 판단할 수 없음
- 결제 조건·지급 일정 정보가 없어, 지연이 공급사 때문인지 회사 내부 지급 절차 때문인지는 구분할 수 없음
- 한 가지 거래 방식만 포함되어, 거래 방식끼리 비교할 수 없음
- 지급 보류 비교는 0136 한 곳만 확인함
- 이 부분집합은 구매 회사가 사실상 1곳(217,406품목 중 217,404품목)이라, 회사별 비교는 이 데이터로 할 수 없음

다음에 볼 것
- 송장이 입고보다 먼저 온 건과 아닌 건의 지급 소요일 차이가 통계적으로 의미 있는가
- 아직 지급 안 된 건에서 새로 보인 공급사(0104, 0106)도 지연이 심한가
- 월별 지연 비율 추이
